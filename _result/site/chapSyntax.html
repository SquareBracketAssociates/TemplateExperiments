1 Microdown syntax

Microdown is a small, regular variant of Markdown designed for writing books and documentation in Pharo. Its syntax has two levels:

  • inline elements live inside a paragraph: emphasis, code, links, references;
  • block elements span one or more lines: paragraphs, headers, lists, code blocks, tables, figures, quotes.

Block elements can carry arguments, written key=value and separated by &. The same syntax names a figure, captions a code block or anchors an equation, so once you know it, you know them all.

1.1 Paragraphs and line breaks

A paragraph is a group of consecutive lines. An empty line ends it.

Inside a paragraph, a new line is not a line break: the lines of a paragraph flow together, on the web site as in the PDF. So you can write one sentence per line, and version control then shows changes sentence by sentence.

To break a line, write <br> where the break goes. For example, an address:

Inria Lille - Nord Europe <br>
Parc scientifique de la Haute Borne <br>
40, avenue Halley <br>
59650 Villeneuve d'Ascq

gives:

Inria Lille - Nord Europe
Parc scientifique de la Haute Borne
40, avenue Halley
59650 Villeneuve d'Ascq

GitHub Markdown gives the same result, but marks a line break with two spaces at the end of the line, which nobody can see in the source. Microdown makes the line break explicit.

1.2 Text formats

You writeYou get
**bold**bold
_italic_italic
~strike~strike
**bold and _italic_**bold and italic

Formats nest, as the last line shows. Text between backquotes is inline code: Object new. To write a character that Microdown would read as markup, put a backslash before it: \* gives *, and \_ gives _.

1.3 Headers

A header is a line starting with one to six #. In a book, # is the title of a part or of the book, ## starts a chapter, ### a section and #### a subsection:

## A chapter
### A section
#### A subsection

Do not skip levels (a #### directly under a ##): numbering counts the missing level as 0 and shows numbers like 1.0.1.

1.3.1 A subsection

This is a subsection, written #### A subsection. The web site numbers it as part of its section.

1.4 Lists

An unordered list item starts with - or *. An ordered item starts with a number followed by . or ); the output numbers items from the first number on.

- A first item
- A second item that is long enough
  to continue on a second line indented by two spaces
  - A nested item, indented by two spaces

1. First step
2. Second step
   - A nested bullet, aligned with the text of its item

gives:

  • A first item
  • A second item that is long enough to continue on a second line indented by two spaces
    • A nested item, indented by two spaces
  1. First step
  2. Second step
    • A nested bullet, aligned with the text of its item

Indentation matters: nested items and continuation lines are aligned with the first character of the text of their item.

1.4.1 Task lists

An item starting with [ ] is a task to do, and one starting with [x] a task done, as in GitHub Markdown:

- [x] Write the chapter
- [ ] Add the figures
- [ ] Check the references

gives:

  • Write the chapter
  • Add the figures
  • Check the references

1.5 Links

[Pharo](https://pharo.org) gives Pharo. A link to another place of the book is not written with a URL but with an anchor reference, presented in Chapter 2.

1.6 Figures

A figure uses the Markdown image syntax. Its arguments end the caption, after a %:

![The Pillar logo.%width=40&anchor=figPillar](figures/pillar.png)

  • The text between the brackets and before the % is the caption; it may contain inline formats.
  • width is a percentage of the width of the page.
  • anchor names the figure, so that the text can refer to it with an anchor reference: the anchor between *@ and @*. Writing Figure *@figPillar@* gives Figure 1.1: the reference shows the number of the figure. Anchors and references are presented in Chapter 2.
  • The path is relative to the file that contains the figure. Always write the file extension (.png, .jpg, .svg): LaTeX finds a file without it, a browser does not.

Place a figure on a line by itself, separated from the text by empty lines.

1.7 Code blocks

A code block is enclosed between two lines of three backquotes. The first line may name the language and add arguments:

  ```pharo|caption=Loading Zinc HTTP Components&anchor=lstZinc
  Metacello new
      repository: 'github://svenvc/zinc/repository';
      baseline: 'ZincHTTPComponents';
      load.
  ```

A code block with a caption or an anchor is a listing: it is numbered, like Listing 1.1.

An anchor alone is enough to refer to a code block with an anchor reference (*@lstFactorial@*, see Chapter 2):

  ```pharo|anchor=lstFactorial
  100 factorial printString size
  ```

Listing 1.2 counts the digits of 100 factorial. It has a number but no caption.

A code block without caption nor anchor is a plain snippet:

Transcript show: 'A plain snippet, without number'

The language changes the highlighting:

  • pharo for Pharo expressions;
  • method for a whole method, whose first line is the method header;
  • text for text written as is.
accept: aVisitor
	"A method, shown with the method language."

	^ aVisitor visitCode: self

1.8 Tables

A table is a sequence of lines starting with |. A line of --- cells after the first line makes it the header.

| Element | Inline | Numbered |
| --- | --- | --- |
| Figure | no | yes |
| Listing | no | yes |
| Emphasis | yes | no |
ElementInlineNumbered
Figurenoyes
Listingnoyes
Emphasisyesno

Without the --- line, the table has no header:

first1
second2

Cells hold inline elements only. Keep tables short and narrow: they must fit a printed page.

1.9 Quotes

Lines starting with > form a quote:

> Simplicity is prerequisite for reliability.
> Edsger W. Dijkstra
Simplicity is prerequisite for reliability. Edsger W. Dijkstra

1.11 Comments

A line starting with % is a comment: it stays in the source and appears in no output.

% TODO: add a figure of the inspector here.

1.12 Document metadata

A file may start with metadata written in JSON:

{
  "title" : "A cool documentation",
  "authors" : "S. Ducasse"
}

The book-wide settings, such as the title, the writers and numbering, live in pillar.conf, presented in Chapter 6.
